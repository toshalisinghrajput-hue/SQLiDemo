SQL Injection Guide

Understand the vulnerability, explore the demonstration, and learn how secure queries prevent SQL injection.

What is SQL injection?

SQL injection (SQLi) is a security vulnerability that occurs when untrusted input is inserted into a database query without proper protection. An attacker may alter the intended query, potentially accessing or changing data.

Use responsibly: This demo is for education only. Test only within this application or on systems you own or have explicit permission to assess. Never enter real credentials or personal data.

Vulnerable VS Secure

Vulnerable Approach

In a vulnerable implementation, user input is directly concatenated into SQL statements. This allows attackers to manipulate the query structure.

String query = "SELECT * FROM users
 WHERE username = '" + userInput + "'";

For example, if userInput is concatenated with [' OR '1'='1] or
[' #], the query becomes:

SELECT * FROM users WHERE username = '' OR '1'='1';

Secure Approach

In a secure implementation, prepared statements or parameterized queries are used. This ensures that user input is treated as data, not executable code.

PreparedStatement stmt = connection.prepareStatement
("SELECT * FROM users WHERE username = ?");

Here, the ? placeholder is replaced with the user input in a safe manner, preventing SQL injection.

How to prevent SQL injection

  • Use prepared statements or parameterized queries.
  • Validate input with allowlists and appropriate type checks.
  • Apply least-privilege permissions to database accounts.
  • Keep frameworks, drivers, and database software updated.
  • Log and monitor suspicious database activity without exposing secrets.
